# Project Architecture Rules (Non-Obvious Only)

- `TODOBL` (`*SRVPGM`) owns all CRUD logic and both file handles: `TODOLF` for sequential reads (subfile load, ID generation) and `TODOPF` for mutations. They are not interchangeable. `TODOMAIN` (`*PGM`) is a thin UI shell that calls `TODOBL`'s 11 exported procedures — it declares no database files of its own, only the display file `TODODSPPF`.
- `TODOMAIN` declares `TODODSPPF USROPN` and opens it explicitly with `OPEN TODODSPPF` inside `Main()`. `OpenFiles`/`CloseFiles` (exported from `TODOBL`) only manage `TODOLF`/`TODOPF`. A future procedure that needs database files open before `Main()` calls `OpenFiles()` will abend.
- The subfile (`TODOSFL`) is a full-page subfile with `SFLSIZ(99)` — it is completely cleared and reloaded from scratch on every return to the list screen (`LoadSubfile`, in `TODOMAIN`). There is no incremental update path.
- `TDDONE='1'` records are filtered in RPG (`LoadSubfile`), not at the logical file level — `TODOLF` has no select/omit. Adding a select/omit to the LF would require recompiling `TODOLF`, `TODOBL`, and `TODOMAIN`.
- `GetNextId` (in `TODOBL`) is a max-ID-plus-one scheme, not a sequence object — concurrent users on a multi-user system could generate duplicate IDs. This is acceptable for pub400.com single-user use only.
- Program entry is `Main();`, called at line 122 of `TODOMAIN.RPGLE` — right after the prototype/declaration section and before any `DCL-PROC` body, not at the end of the file.
- `EXTPROC` names are uppercase strings (e.g. `EXTPROC('OPENFILES')`). Both `TODOBL.RPGLE`'s procedure definitions and `TODOMAIN.RPGLE`'s prototypes must use the same uppercase string; any mismatch causes an unresolved-symbol bind error.
- `QBNDSRC/TODOBL.BND` lists exported symbols explicitly via `STRPGMEXP`/`EXPORT SYMBOL`/`ENDPGMEXP`. Adding a new exported procedure to `TODOBL.RPGLE` requires a matching `EXPORT SYMBOL` entry in `TODOBL.BND` — TOBi builds `TODOBL.SRVPGM` with `EXPORT(*SRCFILE)`, so missing entries silently drop the export.
- Deploy and compile steps do not need to be planned as manual tasks — they are handled entirely by GitHub Actions CI. The Bob Stop hook is a no-op. Plans should focus on source changes only; push to a feature branch to deploy into `MBPRICE1` (via `deploy-dev.yml`), or push to `main` to deploy into `MBPRICE2` (via `deploy-test.yml`).
